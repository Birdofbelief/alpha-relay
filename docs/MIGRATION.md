# 从单文件脚本迁过来

**适用对象**：一个几千行的、能跑的量化脚本，策略、取数、投递、风控全在里面。

先说结论：**不要重写。** 一次重写会把「已有的正确行为」和「还没验证的新代码」
混在一起，出了分歧你分不清是哪边的错。下面是一条能随时停下的路径。

---

## 零、动之前：把「现状」冻住

迁移的第一件事不是写代码，是**给现网行为留一份可比对的基线**。

1. 把当前产出的信号**原样存一份**（至少一个交易日的 `trade_signals.json`）。
2. 确认你能**离线**重放那一天的决策 —— 如果不能（策略里读文件、发请求、
   取墙上时钟），先看第二节。**「能回放」是整条迁移路径的地基**：
   后面每一步的验证都靠它。

> ★ 这一步看起来最不像「进度」，但它是唯一能让你在第三步确认
> 「我只是重构了，没改变行为」的东西。跳过它的迁移，最后都退化成
> 「跑起来没报错，应该是等价的」—— 那不是验证。

---

## 一、对应关系：你脚本里的哪一坨，变成这里的什么

| 你脚本里的一坨 | 迁到这里 | 备注 |
|---|---|---|
| 选股/打分/买卖判断 | **`Strategy.decide(ctx)`** | 你的 alpha，**留在仓库外** |
| 拉行情 / 算因子用的历史 | `MarketData`（`ctx.history` / `ctx.price`） | 因子计算若依赖历史，改成从 `ctx` 取 |
| 拼 JSON、发请求、重试 | `Transport` | 见第三节 |
| `if 数据坏了: return` 之类的保护 | **`Gate`** | 见第四节 |
| `while True` + `sleep` + 判断时间 | `Runner` / `schedule` | 补执行窗口、失败上限都在里面 |
| `if __name__ == "__main__"` 里那堆初始化 | `build_chain()` / `Config` | —— |

## 二、第一步：只动策略，其余不碰

**目标：让你的策略能在一个纯函数签名下跑起来，并且离线重放得出和现网一样的信号。**

```python
from signalchain import Strategy, ACTION_BUY, ACTION_SELL

class MyStrategy(Strategy):
    name = "my_strategy"

    def universe(self):
        return [...]                    # 标的池：链路据此决定拉哪些行情

    def warmup_bars(self):
        return 120                      # 链路据此决定历史缓存拉多长

    def decide(self, ctx):
        ...                             # 你原来的判断逻辑，原样搬进来
```

要过的三关：

1. **`decide()` 里不能有任何 I/O。** 原来的 `akshare.xxx()` / `open(...)` /
   `requests.get(...)` 全部改成从 `ctx` 取。`ctx` 没有的东西，要么加一个
   `AuxSource`（见第五节），要么说明它是链路该管的。
2. **时间戳用 `ctx.signal(...)`，不要自己 `datetime.now()`。** 见
   [`WIRE_CONTRACT.md`](WIRE_CONTRACT.md) 第二节：信号 id 是幂等键，
   掺了墙上时钟，回放会生成一批全新 id，「这条处理过没有」永远答「没有」。
3. **不要吞掉取数异常。** `ctx.history()` 取不到会抛；要「取不到算没有」
   就用 `ctx.try_history()` 拿 `None`。**一只标的取不到历史**和**本轮没有信号**
   长得一模一样，用裸 `except: pass` 盖住就成了一次静默漏判。

**这一步的验收**：`py -m pytest` 里那组策略纯度绊线能过
（`tests/test_strategy_contract.py` 的做法可以照抄到你的仓库），
并且离线重放那一天的输出与基线一致。

## 三、第二步：换投递后端

**先不要换。** 用 `FileTransport` 在新目录里跑一轮：

```python
from signalchain import build_file_chain
chain = build_file_chain("./runtime", strategy="./my_private.py")
result, fills = chain.step()
```

确认四个 channel 的字节都对了（这一步有现成的对照工具：拿
`tests/golden/*.json` 当参照，看字段名/后缀/时间格式是否一致），
再换成 Gist：

```python
chain = build_chain(strategy="./my_private.py")     # transport="gist" + 环境变量凭据
```

> ★ **Gist 只是一个内置的参考实现，不是这条路线的终点。** 本文件拿它举例，
> 是因为它跨机器、零运维、且本仓库有完整实现。**同机部署用 `file` 就够，
> 一个变量都不用配**；跨机器但不想依赖 Gist 的话，对象存储 / 自建 HTTP /
> 网络盘都可以 —— 实现 `Transport` 的三个方法（`read` / `write` / `describe`）
> 就完了：后端类放在**仓库外**的 `.py` 文件里，让 `SC_TRANSPORT` 指过去，
> 下面这些步骤一个字都不用改，这个仓库里的文件也一行都不用动。
>
> 反过来说，**换存储换不掉任何一条约束**：单一写入者、幂等键、闸门方向，
> 全都与后端无关。

凭据**一个都不在源码里**，全部从环境变量读 —— 变量名、含义与默认值见
[`.env.example`](../.env.example)（`cp .env.example .env` 后填自己的值）。
`SC_GIST_ID` 要按**凭据**对待：secret gist **不是 private**，
它是「不被检索到」，不是「访问不了」。

### ★★★ 迁移期最危险的一件事：两个写入者

**换后端的那一刻，旧脚本必须已经停了。** 不能让新旧两条链同时往同一个 gist 写 ——
Gist 的更新是 read-modify-write、**非原子**，两边都会以为自己写成功了，
而后写的静默覆盖先写的。

这不是理论担忧，也不是「小心点就行」：

- 定时任务、手动补跑、另一个窗口里开着的调试进程 —— **都算第二写入者**
- 覆盖是**静默**的，所以你不会看到任何报错，只会在收盘后对账时发现
  「信号怎么少了几条」
- 所以这条约束在本框架里是**代码强制**的（`SingleWriterGuard`），不是注释约定

**建议**：迁移期换一个**全新的 gist**。两边物理隔离，比任何纪律都可靠；
验证通过后再切回正式的那个。

### ★★ 但新 gist 的 `positions` channel：**种错比不种更坏**

换新 gist 之后那个 gist 是空的。「`positions` 里放什么」看起来无关紧要，
实际**决定闸门开不开**：

| 你放进去的 | 框架读成 | `PositionsSyncedGate` |
|---|---|---|
| **键不存在**（什么都不放） | 「**未知**」—— 执行端还没报过 | **拦下买入**，卖出照常 |
| `{}` 或 `[]` | 「**已知：确认空仓**」 | **放行** —— 于是照常开新仓 |
| `{"positions": {…}, "cash": …, "total_value": …, "update_time": …}` | 「已知：这些持仓」 | 放行（对账确实发生了） |

关键在于：**`{}` 会被解析成一张合法的空持仓表，而不是一个错误。**
这不是 bug —— 「从没报过」与「报过、是空的」在风控上是**相反**的两个结论，
这个区分是被测试钉死的（`tests/test_store.py` 里那条叫「未知 ≠ 空仓」）。
但正因为它合法，**往新 gist 里种一个 `{}`，就等于替执行端宣布了一次根本没发生的对账** ——
接着策略照常开新仓，而执行端那侧可能一次都还没报过。

**真实项目里这个坑有两个面**：一面是**忘了种**（gist 里缺文件，监控直接报异常）；
另一面是这里说的 —— **种了，但种成空的**。后者不报任何异常，
只会安静地把买入闸门打开。**它更坏，因为它看起来像「已经处理过了」。**

> **本框架的立场：不种比种错好。** 什么都不放 → 判「未知」→ 只卖不买，是安全的降级；
> 种一个空的 → 判「确认空仓」→ 正常买入，是**错的放行**。
>
> **自查**：种完跑一轮，看日志/心跳里的 `positions_synced`。
> 它若是 `true` 而执行端根本还没报过 → **你种错了**，把那个键删掉。

## 四、第三步：把散落的保护收成闸门

你脚本里大概散着一些「数据不全就不做」的判断。这一步把它们的**方向**想清楚，
然后收进 `Gate`：

| 现在散在各处的判断 | 归到 |
|---|---|
| 「行情取不到就全部跳过今天」 | `QuoteIntegrityGate` |
| 「持仓没同步成功就不许买」 | `PositionsSyncedGate` |
| 「辅助数据缺了就只做卖出」 | `AuxDataGate` |

**关键不是搬代码，是确认方向。** 见 [`DESIGN_NOTES.md`](DESIGN_NOTES.md) 第一节：
每个「失败时怎么办」都要问一遍「反过来做会怎样」，三个闸门的答案**都不一样**。
搬的过程中最容易发生的事，是把一个**故意不对称**的闸门「顺手统一」成全停 ——
那会把止损一起停掉。

## 五、第四步：辅助数据（如果有）

配额外的数据（行业分类、外部信号、财报……）用 `AuxSource` 接：

```python
class MyAux(AuxSource):
    name = "industry"
    def fetch(self, ctx):
        ...                     # 取数，返回 AuxResult
```

框架负责**取、判成败、汇总**，策略只管**读**。这样「辅助数据缺失」这件事
就有了统一的位置和统一的处理（`AuxDataGate`），而不是散在策略里某个 `if`。

## 六、迁移中必须守住的三条

1. **线格式一个字节都不许变**（如果执行端不动）。
   改之前逐条过 [`WIRE_CONTRACT.md`](WIRE_CONTRACT.md) 第七节的兼容性清单。
   **后缀、时间格式、终态集合**这三样要**各自单独想一遍** ——
   它们都有「看起来该统一、实际不能统一」的理由。

2. **迁移期不要改策略逻辑。** 一次只改一件事。行为变了之后，
   你分不清是迁移引入的，还是策略改动引入的。

3. **每一步都要有「随时能退回去」的点。** 保留旧脚本与旧 gist 直到新链
   验证通过。迁移不是上线，不需要一次到位。

---

## 七、什么时候**不该**迁

- 脚本只有几百行、单文件、够用 —— 分层的收益抵不过抽象的成本。
- 策略里没有可复用的工程部分（没有投递、没有调度、没有风控）——
  那本框架提供的东西你一样都用不上。
- **你还没有一份能离线重放的基线。** 先建基线；没有它，迁移就是盲改。
